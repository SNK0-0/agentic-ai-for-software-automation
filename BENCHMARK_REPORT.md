## New polyglot integration benchmark

The frozen fixture in `examples/mixed_service` consists of a TypeScript client
and a Python Flask-style API module. It has two manually labelled, literal
method/path bindings:

| TypeScript source | Expected Python handler | Recovered |
|---|---|---:|
| `frontend/client.ts:loadGreeting` — `GET /api/greeting` | `backend/api.py:get_greeting` | Yes |
| `frontend/client.ts:sendEcho` — `POST /api/echo` | `backend/api.py:echo` | Yes |

This produces **100% labelled binding recall (2/2)** and **100% precision
within this fixture (2 correct links, 0 extra links)**. The links are represented
as `HTTP_CALLS` edges, separate from regular function `CALLS` edges.

The same run produced:

| Graph measure | Value |
|---|---:|
| Source files | 2 |
| Lines of code | 34 |
| Nodes | 22 |
| Hyper-edges | 30 |
| Syntactic / dependency / flow edges | 7 / 9 / 14 |
| Ordinary internal call bindings | 2 of 7 call sites (28.57%) |
| Cross-service HTTP bindings | 2 |
| Isolated nodes | 0 |

The ordinary call-resolution percentage deliberately excludes `HTTP_CALLS`.
The five unresolved ordinary calls are framework/external operations such as
`fetch`, `response.json`, and JSON serialization; they are preserved as
external rather than incorrectly matched to local functions.

Reproduce with:

```powershell
python -m unittest discover -s tests -v
python eval_ckg.py --repo examples\mixed_service
python eval_polyglot.py
```

## Interpretation and limits

These are engineering-validation results, not a claim to replicate the paper's
published real-repository benchmarks. In particular, the legacy retrieval
benchmark is generated by the repository itself, is very small (49 LOC), and
the latency figure is sensitive to local machine timing. The mixed-service
fixture is deliberately narrow and validates only static literal paths and
methods. Dynamic URLs, router prefixes, proxy/gateway rewrites, runtime route
registration, authentication middleware, and JavaScript alias/property flow
are intentionally not inferred.

The next credible benchmarking step is a versioned, independently labelled
set of real mixed-language repositories, with false-positive and false-negative
review for API links.
